# Movie Watchlist

A small JavaScript project for practicing working with arrays of objects, filtering and sorting data, calculating summary values, and managing basic application state.

## Overview

The Movie Watchlist displays a collection of movies and allows users to search, filter, and sort the collection.

I built this project as part of my JavaScript practice, with a particular focus on separating source data, application state, derived data, and rendering. I am also practicing with a consistant project workflow. The UI was created by AI, so I can practice the data portion of the app. The dataset was generated by AI as well.

### Features

Users can:

- View all movies in the watchlist
- See each movie's title, release year, genre, runtime, and watched status
- Filter movies by watched or unwatched status
- Filter movies by genre
- Search for a movie by title
- Sort movies by release year
- Sort movies by runtime
- View summary information about the watchlist

The summary displays:

- Total number of movies
- Number of watched movies
- Number of unwatched movies
- Total runtime of watched movies

## My Approach

Before writing the JavaScript, I analyzed the project requirements and identified the main pieces of data and state the application would need.

The movie collection acts as the application's source data. User choices such as the selected status, genre, search query, and sorting method are stored separately.

The visible movie list is then derived from the movie data and the current application state.

The general data flow is:

```text
Movie Data
    +
Application State
    ↓
Filter
    ↓
Search
    ↓
Sort
    ↓
Visible Movies
    ↓
Render UI
```

Summary values are also calculated from the movie data rather than stored separately.

This helped me think about the application as a flow of data instead of treating filtering, searching, sorting, and rendering as unrelated features.

## Testing

I manually tested the application by checking:

- Each feature individually
- Multiple filters used together
- Search combined with filters
- Sorting combined with filters and search
- Searches with no matching results
- Resetting filters and search
- Summary calculations
- Keyboard interaction
- Different screen sizes
- Browser console errors

Testing combinations of features was particularly important because several controls can affect the same visible movie list.

## What I Learned

One of the main things I learned from this project was the difference between **source data**, **application state**, and **derived data**.

Instead of storing separate arrays for watched movies, unwatched movies, search results, and filtered movies, I can keep a smaller source of truth and derive the information the interface currently needs.

A useful mental model I took from the project is:

```text
Data + State → Derived Data → UI
```

I also learned the importance of building one feature at a time and testing combinations of features after they work individually.
